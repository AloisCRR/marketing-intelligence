# CONTEXT.md — Marketing Intelligence

## Glossary

- **Source**: a curated origin (site/feed/account) with retrieval config. Currently 20 curated sources via RSS + sitemap/hub/url-set lanes, plus premium per-account lanes (one row per account, e.g. `ig:sabrikolod` and `ig:jordisanildefonso` via Apify, ADR-0013); further lanes are added by ADR.
- **Source Inventory**: read-only per-Source listing (`name`, `article_count`, `last_ingest_at`, `cadence`) covering all 22 Sources in the current roster; empty and never-ingested Sources report explicit `0`/`null` instead of disappearing. `last_ingest_at` is the finish time of the most recent successful Ingestion Run (`error IS NULL`).
- **Document / Article**: one normalized retrieved item (title, content, URLs, timestamps, language, hash). The durable evidence unit. A social post maps onto Document (caption→`content`, synthesized title); raw provider payload lives in the `document_payloads` side table, not in Document. Text read out of the post's images lives in the `document_image_texts` side table — one row per frame (`frame_index` in `enumerate_frame_urls` order, cover first; `image_text`, `model`, `extracted_at`; ADR-0014), never merged into the caption. The single read exposes it as `image_texts[]` (ordered frames; `[]` when none), while list payloads carry only `has_image_text` (True when at least one frame holds real text — frames the model found no text in store the `NO_TEXT` sentinel).
- **Read State**: which consumers have marked a Document as read. One row per `(document, reader)` in `document_reads` (caller-supplied free-string reader tag, ≤100 chars, blank rejected; re-mark by the same reader updates its timestamp; `clear` + reader removes one reader, `clear` alone removes all). Every search result, single read, and period bundle item carries `readers` (sorted `{reader, read_at}` pairs; `[]` when unread) alongside the legacy anyone-read summary (`read` bool, `read_at`/`read_by` = latest mark across all readers, NULL = unread). `exclude_read` stays anyone-read. Marking reflects consuming the Document, not reading a digest. _Avoid_: seen, viewed, page mark, digest consumer as actor, anonymous mark
- **Story / Event**: the underlying development multiple documents may cover. The `story_id` column is reserved (nullable) but currently unused — no clustering yet.
- **Topic**: a controlled pillar/region/content-type tag on a Document, drawn from the in-code vocabulary (`marketing_intelligence.topics`). Caller synonyms, case/whitespace variants and retired aliases canonicalize to one slug server-side; unknown tags are rejected (never stored as-is). Writes are append-only with latest-wins (the effective set is exactly the last write; `[]` clears), so the tagging history is retained and vocabulary changes stay additive (retire by aliasing, never deleting). Every search result, single read, and period bundle item carries `topics` (sorted canonical slugs; `[]` when unannotated). Retrieval accepts the same canonical vocabulary as a `topics` filter (a Document matches when it carries any requested slug; an unannotated Document is excluded only when the filter is set, and an empty list adds no constraint).
  _Avoid_: free-text tag, category, entity (named-entity extraction remains out of scope)
- **Ingestion Run**: one execution of `ingest_source_flow` for one source, independently rerunnable. Partial failure is explicit.
  _Avoid_: Flow Run (Prefect implementation term for the same execution), batch run
- **Ingestion Stage**: one fetch / parse / upsert step inside an Ingestion Run, implemented as a Prefect task.
  _Avoid_: Task Run (Prefect implementation term for the same step)
- **Period Context**: a prepared evidence bundle for a caller-given date range (`period`, `recent_articles` — a list of source groups `{source, articles}`, ordered by their first item's position in the global order, each `articles` a list of headlines ordered importance-first by default, recency-first when the floor is cleared). Every source with at least one hit appears; `limit` (1–100, default 50) caps the headlines **per source group**, so a single prolific source cannot monopolise a bundle, and there is no total cap. The default view is annotated-only: omitted `topics` means the digest-priority topic list and omitted `min_importance` means the 0.5 floor (explicit `topics=[]` clears only the topic constraint, explicit `min_importance=None` clears only the floor; both together restore the unfiltered recency-ordered bundle). Each headline carries slim scalars only — `title`, `url`, `canonical_url`, `published_at`, `author`, the Read State summary (`read`, `read_at`, `read_by`, `readers`), `flag_reason`, the capped effective `importance_score`, `topics`, and `has_image_text` — never a per-article `source`, an ordering field, or the full body.
- **Service Adapter**: the single validated interface (`marketing_intelligence.service`, `MAX_LIMIT=100`, `InvalidRequest`) behind both caller surfaces; stdlib-only, no HTTP/MCP imports.
- **Extraction Flag**: a marker that a Document's content was improperly extracted, with reason + detail + reporter + timestamp. Agents file and clear them through `flag_extraction` (seven reasons, `unrecoverable` included); the ingestion pipeline also files the terminal `unrecoverable` reason itself, reporting as `system`, when a document's whole article-content chain fails and only the thin RSS body survives (pipeline context: ADR-0012). Flagged Documents stay hard-capped at 0.3 importance whichever lane filed them.
  _Avoid_: Page mark, quality flag (factual accuracy is out of scope)
- **Importance**: an agent-written 0–1 score on a Document with optional rationale + reporter, stored append-only (latest write wins, full history retained). Flagged or paywalled Documents are hard-capped at 0.3 server-side so they can never outrank clean evidence; every search result and single read carries the latest annotation (`importance_score`, `importance_rationale`, `importance_reporter`, `importance_updated_at`; NULL when unannotated), while period bundle headlines carry only the capped effective `importance_score`. Retrieval accepts an importance floor (`min_importance`): a NULL score is excluded only when a floor is set (and never ordered above annotated evidence — floored queries order importance-first `NULLS LAST`, unfiltered ones stay recency-first).
  _Avoid_: rank, popularity, trend score
- **API / MCP**: two thin, parity-guaranteed surfaces over the service adapter — HTTP (`GET /search`, `POST /period-context`, `GET /article`, `GET /sources` with the Source Inventory, `POST /flag-extraction`, `POST /mark-read`, `POST /importance`, `GET /importance`, `GET /vocabulary`, `POST /topics`, `POST /digest-picks`, `GET /digest-picks`, `DELETE /digest-picks`, 422 on `InvalidRequest`) and MCP (13 tools: `search_articles`, `get_period_context`, `get_article`, `list_sources_inventory`, `flag_extraction`, `mark_article_read`, `set_importance`, `get_importance`, `list_vocabulary`, `set_document_topics`, `record_digest_picks`, `get_digest_picks`, `clear_digest_picks`, same payloads by construction). Both retrieval read paths accept the annotation filters `min_importance` and `topics` (canonicalized server-side, unknown → 422) plus the existing `sources`/`limit`/`exclude_read`. Search result dicts are 19-key (7 base + 4 flag + 3 read + 4 importance + 1 topics); period bundle headlines are the slim 13-key set grouped by source.
- **Digest Pick**: one Document selected for a dated digest edition, traced in `digest_picks` — one row per `(digest_date, document_id)` with optional reporter and a recorded timestamp. Recording is a reconcile against the stored set: re-recording the URL set a human edited the digest down to returns `added`/`removed` canonical identifiers, the re-scoring signal for those Documents' importance. `clear_digest_picks(digest_date)` drops a discarded edition's trace. Unlike Importance/Topic history this table is a current set, not an append-only audit. The trace is read digest-first (`get_digest_picks`); Document-first discovery cross-references those picks with `get_article`, deliberately keeping the frozen retrieval payloads (ARTICLE/SEARCH/PERIOD key sets) unchanged.
  _Avoid_: digest article, edition, publication (the trace records picks, not the digest text)

## Current scope (evolving)

These are the defaults the system runs today, not fixed constraints: each entry records the current posture and can be extended or replaced by an ADR (ADR-0012/0013/0014/0016 are existing precedents).

- RSS + sitemap/hub/url-set: all 20 curated feed sources, counted as effective runtime lanes — 4 RSS stanzas and 16 discovery lanes (Swarovski's curated stanza declares hub discovery directly — a retrieved feed is dead, so its URL is retained as provenance only and never fetched). The ADR-0013 premium lanes are separate: `ig:sabrikolod` and `ig:jordisanildefonso` are the 21st/22nd Sources and each runs its own per-account Apify lane (`apify-premium`), never the impersonated chain.
- Deterministic by default: the current pipeline runs no LLM, no embeddings, and no automatic topic/entity extraction (documents carry agent-written controlled Topics above; named entities remain deferred). That is a current default, not a ban — lanes that add models are adopted by ADR, as ADR-0013 (paid per-account vendor lane) and ADR-0014 (opted-in Instagram pilot) already show. The pilot runs a pinned vision model (`temperature: 0`, exact-transcription prompt) to read frame text into `document_image_texts`; it transcribes only — no summarization, classification, or scoring — and the caption stays the Document's `content`.
- Annotate lane (ADR-0016): every Document is classified post-ingest by the pinned Jev decision model (`reporter='jev'`, same latest-wins as agent writes) — pillar/region/content-type `topics` plus a native `importance_score` judgment. `get_period_context` defaults to the digest-priority topic list when the caller passes no `topics` and to the 0.5 importance floor when the caller omits `min_importance` (default view is annotated-only and importance-ordered; explicit filters always win and search stays unfiltered).
- API-only surface today: search + `get_period_context(from, to)`; no Monday digest schedule yet.
- Retrieval: curated sources only — plain HTTP + RSS parsing and sitemap/hub/url-set discovery; no universal scraper. Feed and sitemap URLs are fetched impersonated-only: no Markdown reader or scraper ever sees a feed or sitemap URL. Hub listings are article-chain fetches (impersonated primary → Jina reader fallback), so a walled hub still yields its article links — HTML anchors or, when the reader serves it, Markdown links; an article body delivered as reader Markdown supplies its own title/timestamp/author header block. Article content walks one shared three-leg chain (`enrich.article_content_chain`): impersonated primary → Jina reader → Firecrawl scrape as the paid terminal leg, explicitly recorded in ADR-0012 (article bodies only); provider Markdown is stored as-is after a thin-check, HTML extraction is trafilatura-only, and robots-Disallow paths are planned like any other, with crawl-delay, per-host pacing, and newest-first budgeting still bounding the fetch rhythm.
- Platform posture: Postgres 18 + pgvector in local compose, and Prefect `@flow/@task` against a local server for ingest (`prefect server start` required; VPS deploy later). B2 deferred.
